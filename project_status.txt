1. PROJECT PURPOSE, CURRENT STATUS, AND FEATURE MATRIX
================================================================================
1.1 PROJECT PURPOSE
TyreTrace is an engineering digital twin and degradation inference system for Formula 1 racing.
Because FIA technical regulations and commercial broadcast policies strictly prohibit public access
to real-time tyre internal sensors (carcass/tread thermal arrays, internal pressures, dynamic tread
depth, slip angles, and individual wheel speeds), tyre degradation cannot be directly observed from
public telemetry feeds.

TyreTrace solves this fundamental observability barrier via a deterministic 4-stage physics pipeline:
  1. Ingests raw telemetry (Speed, Throttle, Brake, Gear, RPM, DRS, Weather, Stint Metadata).
  2. Runs a first-principles Physics Digital Twin to compute expected vehicle acceleration.
  3. Computes the Actual-vs-Expected residual: r_ax(t) = ax_actual(t) - ax_expected(t).
  4. Filters non-tyre physical confounders (DRS, threshold braking, engine transients, aero speed scaling).
  5. Infers the Tyre Degradation Index (TDI) [0–100] through deterministic physics scoring fused with
     an interpretable machine learning baseline (Random Forest / Gradient Boosting).
  6. Visualizes the car and tyres in real time across a high-performance React dashboard, WebGL Three.js
     canvases, and an external Blender 3D Digital Twin via WebSocket streaming.

1.2 CURRENT STATUS
The core foundational pipeline (Phases 1 through 11) is fully implemented, verified, and operational.
The backend serves both historical replay and real-time streaming over REST and WebSockets.
The frontend displays multi-page race intelligence, interactive 3D digital twins, and explainability cards.
However, NO autonomous decision-making, LLM agent, pit-stop optimization, or strategy execution engine
currently exists in executable code.

4.2 IMPLEMENTED PHYSICS CALCULATIONS & EXACT FORMULAS
1. Aerodynamic Drag Force (Quadratic with Velocity):
   F_drag = 0.5 * rho * Cd * A * (v^2) * sgn(v)
   • Inputs:
     - speed_mps (v) [m/s] — Vehicle true ground speed
     - air_density (rho) = 1.225 kg/m^3 (Standard sea-level air at 15°C)
     - cd = 0.85 (Medium-downforce F1 regulation baseline)
     - frontal_area_m2 (A) = 1.50 m^2
   • Output: expected_drag_n [N]
   • Note: Strictly increases quadratically with speed; opposes motion direction.

2. Rolling Resistance Force:
   F_rolling = Crr * m * g
   • Inputs:
     - mass_kg (m) = 798.0 kg (2022+ F1 minimum technical regulation mass)
     - crr = 0.015 (Smooth racing asphalt rolling resistance coefficient)
     - gravity (g) = 9.80665 m/s^2
   • Output: expected_rolling_resistance_n = 117.4 N (constant at non-zero speed).

3. Total Normal Vertical Load:
   Fz_total = m * g + F_aero
   • Inputs:
     - mass_kg (m) = 798.0 kg
     - F_aero = 0.0 N (Nominal downforce separated in baseline MVP)
   • Output: expected_vertical_load_n = 7825.7 N.

4. Dynamic Longitudinal Load Transfer:
   DeltaFz = (m * ax * h) / L
   • Inputs:
     - mass_kg (m) = 798.0 kg
     - ax = ax_expected [m/s^2]
     - cg_height_m (h) = 0.30 m (Center of gravity height)
     - wheelbase_m (L) = 3.60 m (Modern F1 wheelbase)
     - static_front_fraction = 0.45 (45% front, 55% rear static weight bias)
   • Outputs:
     - Fz_front = Fz_front_static - DeltaFz (under acceleration; transfers rearward)
     - Fz_rear  = Fz_rear_static  + DeltaFz (under acceleration; squat)
     - Fz_front = Fz_front_static + |DeltaFz| (under braking; dive)
     - Clamped to [0, Fz_total] to prevent unphysical negative wheel loads.

5. Effective Tyre-Road Grip & Maximum Friction Force Ceiling:
   mu_eff = mu0 * (1 - D) * f_temp * f_press * f_slip
   F_tyre_max = mu_eff * Fz
   • Inputs:
     - mu0 = 1.60 (Nominal baseline clean dry slick friction coefficient)
     - D = degradation in [0, 1] (0.0 for baseline nominal twin)
     - f_temp, f_press, f_slip = 1.0 (Sensitivities set to nominal when unmeasured)
   • Output: F_tyre_max_total = 1.60 * 7825.7 = 12521.1 N.

6. Modelled Longitudinal Traction Force:
   P_demanded = (throttle_pct / 100.0) * P_max
   F_traction = min(P_demanded / max(v, 4.0), F_tyre_max_total)
   • Inputs:
     - throttle_pct in [0, 100]
     - P_max = 750,000 W (750 kW / ~1000 bhp peak powertrain output)
     - effective_v = max(v, 4.0 m/s) (virtual gearing to avoid division by zero at standstill)
   • Output: expected_traction_force_n [N] (clamped by tyre friction limit).

7. Modelled Braking Force:
   F_brake = min((brake_pct / 100.0) * F_brake_max, F_tyre_max_total)
   • Inputs:
     - brake_pct in [0, 100]
     - F_brake_max = 28,000 N (Peak 4-wheel braking clamp force at 100% pedal effort)
   • Output: expected_brake_force_n [N].

8. Primary Vehicle Net Force & Expected Acceleration:
   F_net = F_traction - F_drag - F_rolling - F_brake
   ax_expected = F_net / m
   • Output: expected_acceleration_mps2 [m/s^2].

9. First-Principles Tyre Thermal Energy Balance (PARTIALLY IMPLEMENTED / GUARDED):
   m_t * cp * (dT/dt) = P_heat - P_loss
   P_heat = Fx * v_slip_x + Fy * v_slip_y
   P_loss = hA * (T_surface - T_ambient)
   • Inputs: tyre_mass_kg (10.5 kg), cp (1450 J/kg·K), hA (25 W/K).
   • Code Enforcement: In interface.py:231-241, because real F1 telemetry does NOT provide wheel
     slip velocities (v_slip_x, v_slip_y) or individual wheel forces (Fx, Fy), this function
     strictly returns (None, "UNAVAILABLE"). It does NOT fabricate synthetic heat generation.

5.2 DERIVATION OF ACTUAL ACCELERATION
Because public FastF1 feeds omit raw accelerometer telemetry, ax_actual is derived numerically:
  ax_actual(t) = (v(t) - v(t - Δt)) / Δt
  • Inputs: v(t) [m/s] from telemetry_frame.vehicle.speed_mps, Δt from timestamps.
  • Quality Guards:
    - If v(t) is None or NaN: status = MISSING_INPUT.
    - If initial frame in session (no prior sample): status = MISSING_INPUT.
    - If Δt <= 0.0: status = INVALID_DT ("Non-positive or duplicate delta time").
    - If Δt < 0.001 s (1 ms): status = INVALID_DT ("Sub-millisecond jitter below threshold").
    - If |ax_actual| > 60.0 m/s^2 (~6.1g): status = NUMERICAL_OUTLIER.

5.3 RAW AND NORMALIZED RESIDUAL FORMULAS
1. Raw Acceleration Residual:
   r_ax(t) = ax_actual(t) - ax_expected(t)
   • Unit: m/s^2.
   • Meaning: A negative residual indicates the vehicle accelerated slower (or decelerated harder)
     than the first-principles physics twin predicted.

2. Normalized Acceleration Residual:
   r_ax_norm(t) = r_ax(t) / max(|ax_expected(t)|, epsilon)
   • Default epsilon = 1.0 m/s^2.
   • Prevents divide-by-zero singularities during coasting or steady-state velocity.

5.4 SMOOTHING, TREND SLOPE, AND PERSISTENCE RATIO
• Linear Slope (Delta r / Delta t) over rolling window:
  slope = sum((t_i - mean_t) * (r_i - mean_r)) / sum((t_i - mean_t)^2)
  - Numerator / denominator computed with float64 precision; returns 0.0 if denominator < 1e-9.
• Trend Classification (classify_trend in features.py:66-92):
  - If slope > +0.08 m/s^2 per second: INCREASING.
  - If slope < -0.08 m/s^2 per second: DECREASING.
  - Otherwise: STABLE.
  - If isolated peak > 3.5 * std over <= 15 frames: SPIKE.
• Persistence Ratio (compute_persistence_ratio in features.py:46-64):
  persistence_ratio = (count of valid samples where |r_ax| >= threshold) / total_valid_samples
  - Default persistence_threshold = 1.0 m/s^2.
  - Measures the fraction of the temporal window exhibiting sustained discrepancy.
• Residual Quality Confidence (calculate_residual_quality_confidence in features.py:153-174):
  score = (valid_samples / total_samples) - outlier_penalty - dt_penalty
  - Penalizes sub-millisecond timestamps and numerical outliers. Evaluates data integrity, NOT wear.

6.2 SCIENTIFIC PRINCIPLE
A negative residual r_ax does NOT automatically mean tyre degradation. Many non-tyre physical factors
cause the car to produce less forward acceleration than expected:
  • Driver opening DRS flap reduces drag by 30–40% (positive residual spike).
  • Driver applying hydraulic brakes introduces massive unmodelled retarding forces.
  • Driver lifting off throttle or shifting gears introduces transient driveline lag.
  • Vehicle travelling > 252 km/h enters nonlinear aerodynamic regimes where baseline Cd is inaccurate.
  • Ambient rain or wet track drops asphalt friction mu by 40–60%.
  • Timestamp jitter creates mathematical derivative artifacts.

6.4 NON-TYRE EXPLANATION SCORE & TYRE EVIDENCE QUALITY
• non_tyre_explanation_score in [0.0, 1.0]:
  Sum of active confounder weights multiplied by individual confounder strengths:
  score = min(1.0, sum(weight_i * strength_i for each active confounder))
  (Explicitly NOT a probability; it is an index of physical confounding presence).

• tyre_evidence_quality in [0.0, 1.0]:
  If quality_status != VALID: tyre_evidence_quality = 0.0.
  Otherwise: tyre_evidence_quality = max(0.0, 1.0 - non_tyre_explanation_score).
  Context Modifier: If tyre_age <= 3 laps, tyre_evidence_quality is capped at 0.35.

7.2 EXACT DEFINITION: WHAT TDI REPRESENTS AND DOES NOT REPRESENT
• WHAT TDI IS:
  The Tyre Degradation Index (TDI) is a normalized, unitless severity index in [0.0, 100.0] representing
  the weight of evidence that unexplained vehicle deceleration deficits are attributable to tyre grip
  loss, evaluated in the context of completed tyre laps, residual persistence, and absence of confounding.
• WHAT TDI IS NOT:
  - It is NOT physical tread depth in millimeters (mm).
  - It is NOT remaining tyre thickness or rubber loss mass (grams).
  - It is NOT a failure probability or puncture likelihood.
  - It is NOT telemetry ground-truth; it is a physics-informed inferred diagnostic metric.

7.3 TDI SCORING FORMULA AND ATTENUATION
The TDI engine computes 6 normalized components in [0.0, 1.0]:
  1. s_res   : Residual Severity = min(|residual| / 3.0, 1.0)               (Weight: 0.25)
  2. s_pers  : Persistence Score = persistence_ratio                       (Weight: 0.25)
  3. s_trend : Degradation Trend Score = min(slope / 0.5, 1.0) * consistency (Weight: 0.15)
  4. s_age   : Tyre Age Score:                                              (Weight: 0.20)
               - 0–3 laps: 0.0 | 4–10 laps: 0.2 | 11–20 laps: 0.5 | 21–30 laps: 0.8 | >30: 1.0
  5. s_ev    : Evidence Quality Score = tyre_evidence_quality              (Weight: 0.15)
  6. s_conf  : Confounder Penalty = non_tyre_explanation_score

Raw Evidence Synthesis:
  raw_evidence = (0.25 * s_res) + (0.25 * s_pers) + (0.15 * s_trend) + (0.20 * s_age) + (0.15 * s_ev)

Confounder Attenuation (Attenuation Coefficient = 0.70):
  attenuation = 1.0 - (0.70 * s_conf)
  qualified_score = max(0.0, min(1.0, raw_evidence * attenuation))
  TDI = round(qualified_score * 100.0, 2)  # Clamped strictly to [0.0, 100.0]

7.4 TDI SEVERITY STATES & THRESHOLDS
• 0.0 – 20.0  : HEALTHY_LOW_EVIDENCE
• 20.1 – 40.0 : EARLY_DEGRADATION
• 40.1 – 60.0 : MODERATE_DEGRADATION
• 60.1 – 80.0 : HIGH_DEGRADATION
• 80.1 – 100.0: SEVERE_DEGRADATION

7.5 TDI CONFIDENCE SCORE
Confidence in [0.0, 1.0] reflects observation trustworthiness, NOT tyre health:
  confidence = tyre_evidence_quality * (1.0 - 0.5 * non_tyre_explanation_score) * sample_factor * age_factor
  • sample_factor = max(0.1, samples / 10) if samples < 10 else 1.0
  • age_factor = 1.0 if tyre_age_laps is available, else 0.8
  • Note: A high TDI with low confidence is mathematically valid (e.g. large deficit under heavy rain).

The repository maintains strict engineering boundaries between measured, derived, modelled, and

  • Throttle (0–100%)
  • Brake (0–100% or 0/1 indicator)
  • Gear (0–8, -1)
  • Engine RPM
  • DRS status code (0, 1, 8, 10, 12, 14)

B. DERIVED TELEMETRY (Calculated Numerically from Measured Values):
  • Longitudinal Acceleration: ax_actual = Δv / Δt (derived with jitter guards in backend/residual/residual_engine.py)
  • Lap Relative Distance: 0.0 -> 1.0 (derived in backend/telemetry/track_mapper.py)
  • Temporal Window Features: rolling means, standard deviations, min/max, jerk (Δax / Δt)

C. MODELLED VALUES (Calculated using Physics & Engineering Assumptions):
  • Aerodynamic Drag Force: F_drag = 0.5 * rho * Cd * A * v^2
  • Rolling Resistance Force: F_rolling = Crr * m * g
  • Expected Powertrain Traction Force: F_traction = P_max / v
  • Expected Deceleration Force: F_brake = brake_pct * max_brake_clamp
  • Expected Longitudinal Load Transfer: DeltaFz = (m * ax * h) / L
  • Expected Acceleration: ax_expected = F_net / m
  • Tyre Degradation Index: TDI [0–100]

D. EXPLICITLY UNAVAILABLE CHANNELS (Maintained strictly as None / null in Replay Mode):
  • Tyre Internal Pressures (FL, FR, RL, RR pressure_bar)
  • Tyre Bulk & Carcass Temperatures (FL, FR, RL, RR surface_temp_c, carcass_temp_c)
  • Individual Wheel Rotational Speeds (wheel_speed_mps)
  • Longitudinal Slip Ratio & Lateral Slip Angles (slip_ratio, slip_angle_deg)
  • Individual Corner Normal Vertical Loads (vertical_load_n)
  • Handwheel Steering Angle (steer_angle_deg)
  • True Physical Rubber Tread Depth / Remaining Tyre Life in millimeters

E. DEMO / SIMULATION VALUES (Active ONLY when data_mode == "DEMO_SIMULATION"):
  • frontend/src/services/demoSimulation.ts generates corner-specific wear offsets:
    FL: global_tdi * 1.15 | FR: global_tdi * 0.95 | RL: global_tdi * 0.85 | RR: global_tdi * 0.80.
  • In REAL_REPLAY mode, these slots are returned as available: false, tdi: null.

23. TECHNICAL DEBT, LIMITATIONS, RISKS, AND ARCHITECTURAL CONCERNS
================================================================================
1. Hardcoded UI Placeholders Disagree with Code Capabilities:
   The frontend OverallHealthPage and HomePage display elaborate "Pit Stop Window Calculator" and
   "Compound Lifetime Crossover" cards. Users and judges may believe an AI strategy engine is active,
   when it is currently static HTML/JSX markup.
2. Single-Driver Limitation:
   The FastF1 adapter and replay generator currently extract data for one driver at a time (e.g. VER).
   Real race strategy decisions require knowledge of gaps to competitors and clean air pit exit windows.
3. Aerodynamic Downforce Simplification:
   The physics digital twin currently models aero drag (Cd * A * v^2) accurately, but treats downforce F_aero
   as 0.0 in the baseline vertical load calculation (backend/twin_engine/interface.py:173). Adding downforce
   (Cl * A * v^2) would improve vertical tyre load estimation at speeds > 200 km/h.
4. Single-Wheel Replay vs 4-Wheel Simulation Asymmetry:
   In REPLAY mode, FastF1 corner tyre degradation is strictly null (scientifically accurate).
   In DEMO_SIMULATION mode, heuristic multipliers simulate 4-wheel wear. Transitioning between modes
   causes sudden changes in 3D wheel shader appearances if operators do not realize the mode switch.
5. In-Memory State Non-Persistence:
   RuntimeState stores rolling histories in memory deques. If the backend process restarts, historical
   trends reset to zero until the replay runs again.
6. Vitest JSDOM Mocking Gaps:
   Frontend vitest suite has 2 failing tests due to missing WebGL and IntersectionObserver mocks in jsdom.
