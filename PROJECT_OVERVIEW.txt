================================================================================
  1. WHAT IS THIS PROJECT?
================================================================================

TYRETRACE is a real-time, physics-informed tyre degradation intelligence system 
for Formula 1 racing. It ingests live (or replayed) telemetry data from an F1 car, 
runs it through a chain of physics engines and machine learning models, and 
produces a unified "Tyre Degradation Index" (TDI) — a severity score from 0 to 100 
that indicates how much a car's tyres have degraded during a session.

The system features:
  - A physics-based digital twin of the car (Newton's laws, aerodynamics, 
    rolling resistance, load transfer)
  - An Actual-vs-Expected residual engine that detects anomalies
  - A deterministic confounder analysis engine that filters out non-tyre causes
  - A temporal TDI engine that synthesizes degradation evidence
  - A machine learning model (Random Forest) that fuses AI predictions with 
    physics results
  - A 3D interactive web dashboard with a Three.js race car visualization
  - A Blender integration for photorealistic digital twin rendering
  - Full replay controls to step through historical F1 sessions frame-by-frame

The key scientific principle: The system NEVER fabricates data. When telemetry is 
unavailable (e.g., FastF1 doesn't provide tyre temperatures, pressures, or wheel 
speeds), those fields are explicitly marked as "UNAVAILABLE" / None — never 
invented or simulated (except in explicit DEMO_SIMULATION mode).

================================================================================
  2. HOW THE SYSTEM WORKS — THE UNIFIED INTELLIGENCE PIPELINE
================================================================================

Every incoming telemetry frame passes through a strict sequential chain:

  TelemetryFrame → Physics Twin → Residual Engine → Confounder Engine → TDI Engine → AI Model → Fusion

STEP-BY-STEP PIPELINE:

  Step 1: TELEMETRY INGESTION
  ---------------------------
  - Source: FastF1 Python library (official F1 timing/telemetry data)
  - Data includes: speed, throttle, brake, gear, RPM, DRS, GPS position, 
    track/air temperature, humidity, wind, compound type, tyre age (laps)
  - Data NOT available from FastF1: tyre temperature, tyre pressure, wheel 
    speed, slip ratio, slip angle, corner-specific loads
  - Telemetry is normalized into canonical TelemetryFrame objects with vehicle 
    state, four-corner tyre states, and environment state
  - Sessions can be replayed from pre-recorded JSON files or fetched live

  Step 2: PHYSICS DIGITAL TWIN
  ----------------------------
  - Implements Newton's second law force balance for the car:
      F_net = F_traction − F_drag − F_rolling − F_brake
      a_expected = F_net / m
  - Calculates aerodynamic drag: F_drag = 0.5 × ρ × Cd × A × v²
  - Calculates rolling resistance: F_rolling = Crr × m × g
  - Calculates longitudinal load transfer: ΔFz = (m × ax × h) / L
  - Calculates effective tyre grip: μ_eff = μ0 × (1 − D) × f_temp × f_pressure
  - Also includes tyre thermal energy balance model (for when data is available):
      m_t × cp × dT/dt = P_heat − P_loss
  - Tracks provenance of every parameter: MEASURED, DERIVED, MODELLED, UNAVAILABLE
  - Uses configurable PhysicsParameters (mass=798kg, Cd=1.0, frontal area=1.5m²,
    Crr=0.012, wheelbase=3.6m, etc.)

  Step 3: ACTUAL-VS-EXPECTED RESIDUAL ENGINE
  -------------------------------------------
  - Computes actual acceleration by differentiating speed: a_actual = Δv / Δt
  - Calculates residual: r = a_actual − a_expected
  - Normalizes: r_norm = r / max(|a_expected|, ε)
  - Validates data quality (rejects non-positive Δt, sub-millisecond jitter, 
    acceleration spikes > 60 m/s²)
  - Flags each sample as VALID, MISSING_INPUT, INVALID_DT, or NUMERICAL_OUTLIER
  - Computes rolling window features: slope, persistence ratio, std deviation
  - IMPORTANT: Residual ≠ tyre degradation. It is the unexplained difference 
    between actual and expected behaviour. Degradation is inferred downstream.

  Step 4: CONFOUNDER ANALYSIS ENGINE
  -----------------------------------
  - Evaluates whether the residual can be explained by NON-TYRE factors:
      • DRS (Drag Reduction System) active — affects aerodynamic drag model
      • Heavy braking — threshold braking zones create transient dynamics
      • High throttle — full-power acceleration creates powertrain confounding
      • High speed (> ~250 km/h) — amplifies aerodynamic model uncertainty
      • Transient events — rapid throttle/brake/accel changes (rate-of-change)
      • Tyre age — fresh tyres have lower prior for degradation
      • Compound type — different compounds degrade at different rates
      • Environment shifts — temperature, wind, humidity changes
      • Rainfall — wet conditions fundamentally change tyre behaviour
      • Data quality — invalid or outlier samples reduce reliability
  - Produces two key scores:
      • non_tyre_explanation_score [0, 1]: How much of the residual can be 
        explained by non-tyre factors
      • tyre_evidence_quality [0, 1]: How suitable this observation is for 
        inferring tyre degradation
  - Classifies each frame: STRONG_TYRE_EVIDENCE, MODERATE, LOW, 
    NON_TYRE_DOMINANT, INSUFFICIENT_DATA

  Step 5: TDI ENGINE (Tyre Degradation Index)
  --------------------------------------------
  - The core degradation scoring engine
  - Synthesizes components: magnitude, persistence, trend, age, evidence quality
  - Applies temporal trajectory smoothing (EMA-based) over configurable window
  - Computes trend: RISING, FALLING, STABLE, or INSUFFICIENT_DATA
  - Classifies degradation state:
      • HEALTHY           (TDI < 15)
      • EARLY_WEAR        (TDI 15-35)
      • MODERATE_WEAR     (TDI 35-55)
      • HIGH_WEAR         (TDI 55-75)
      • CRITICAL_WEAR     (TDI 75-100)
      • (with _LOW_EVIDENCE variants when confidence is low)
  - Generates dynamic explainability:
      • evidence[] — reasons supporting degradation inference
      • counter_evidence[] — reasons attenuating confidence
  - Produces lap-level summaries and session-level reports

  Step 6: AI / MACHINE LEARNING MODEL
  ------------------------------------
  - Interpretable Random Forest Regressor (scikit-learn)
  - Trained on physics-informed temporal window features:
      • Residual statistics (mean, std, slope, persistence)
      • Confounder scores (non-tyre, evidence quality)
      • TDI trajectory components
      • Speed, throttle, brake patterns
      • Tyre age and compound encoding
  - Outputs AI_INFERRED_DEGRADATION in [0, 100]
  - NOT ground-truth physical wear — it's a modelled prediction
  - Computes model_reliability score accounting for out-of-distribution inputs
  - Model artifact stored as: data/ml/baseline_model.joblib

  Step 7: PHYSICS + AI FUSION
  ----------------------------
  - Transparent weighted fusion:
      Final TDI = α × Physics_TDI + (1 − α) × AI_TDI
  - Default α = 0.60 (60% physics, 40% AI)
  - Final TDI is clamped to [0, 100]
  - All three scores (physics_tdi, ai_tdi, final_tdi) are always exposed 
    independently — never collapsed

  Step 8: BLENDER PAYLOAD GENERATION
  -----------------------------------
  - Transforms unified pipeline output into compact visualization payloads
  - For Blender 3D scene synchronization (wheel rotation, tyre highlighting,
    camera alignment, HUD overlay)

  - Clearly marked as simulated — for demonstration purposes only

================================================================================
  9. PHYSICS EQUATIONS (REFERENCE)
================================================================================

  Aerodynamic Drag:
    F_drag = 0.5 × ρ × Cd × A × v²

  Rolling Resistance:
    F_rolling = Crr × m × g

  Vertical Load:
    Fz = m × g + F_aero_downforce

  Longitudinal Load Transfer:
    ΔFz = (m × ax × h_cg) / L_wheelbase

  Expected Acceleration:
    a_expected = (F_traction − F_drag − F_rolling − F_brake) / m

  Effective Grip:
    μ_eff = μ₀ × (1 − D) × f_temp × f_pressure × f_slip

  Tyre Thermal Model:
    m_t × cp × dT/dt = (Fx × v_slip_x + Fy × v_slip_y) − hA × (T − T_ambient)

  Pressure-Temperature (Ideal Gas):
    P₂ = P₁ × (T₂ / T₁)

  Residual:
    r_ax = a_actual − a_expected
    r_normalized = r_ax / max(|a_expected|, ε)

  TDI Fusion:
    Final_TDI = α × Physics_TDI + (1 − α) × AI_TDI   (α = 0.60)

  12. KEY SCIENTIFIC POLICIES & LIMITATIONS
================================================================================

  1. TDI is an INFERRED severity index, NOT physical tread depth or rubber loss.
  2. TDI is NOT a failure probability or guaranteed prediction.
  3. Residual ≠ degradation. It is an unexplained physics discrepancy.
  4. Component weights are engineering assumptions (MODEL PARAMETER — DEMO).
  5. FastF1 does NOT provide: tyre temperature, tyre pressure, wheel speeds, 
     slip angles, or corner-specific loads.
  6. Single-lap qualifying telemetry has no multi-lap tyre-age progression.
  7. Longitudinal residuals contain aerodynamic model mismatch.
  8. The system NEVER fabricates unavailable data — always explicit None/null.
  9. In DEMO_SIMULATION mode, corner TDI values are clearly marked as simulated.
  10. AI model is a transparent pseudo-label regressor, not a causal model.
